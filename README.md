# Мессенджер в стиле MAX

Независимый учебный прототип на HTML, CSS и JavaScript. Не официальный клиент MAX.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm start
```

Откройте http://localhost:3000. Для публикации используйте HTTPS.

## Возможности

- Демонстрационные переписки, сохранение демо в localStorage.
- Регистрация, вход, реальные личные и групповые чаты через Socket.IO.
- Поиск чатов и текста в текущем разговоре, ответы, эмодзи.
- Файлы до 10 МБ и запись голосовых сообщений (по нажатию микрофона; повторное нажатие завершает и отправляет запись).
- Избранное как личный чат для заметок.
- Личные аудио- и видеозвонки WebRTC, входящий вызов, отключение микрофона и камеры.
- Демонстрация экрана вместо видеопотока; повторное нажатие возвращает камеру.
- Тёмная тема, размер текста, мобильный интерфейс.

## Демо и реальные звонки

Демо-контакты вымышленные, они не отвечают и не принимают звонки. Кнопки звонка в демо открывают локальный тест устройств; экран никуда не передаётся.

Для настоящей переписки зарегистрируйте два аккаунта в отдельных браузерах / профилях. Через «Новый разговор» откройте личный чат, позвоните и примите вызов со второго аккаунта. Оба пользователя должны быть онлайн.

Для медиа нужны HTTPS (или localhost) и разрешения. Захват экрана зависит от браузера и обычно недоступен на телефоне. Встроенный preview может ограничивать разрешения: откройте приложение отдельной вкладкой. Видео между разными реальными устройствами в этой среде не проверялось.

Для сетей с NAT/фаерволами укажите TURN_URL, TURN_USERNAME, TURN_PASSWORD в .env. Без TURN связь не гарантируется. TURN-сервер и его учётные данные в комплект не входят. Групповые звонки и LiveKit в данной реализации не подключены.

## Работа с вашим server.js

В комплект включён **сокращённый самостоятельный сервер**, а не полная копия предоставленного. Клиент использует совпадающие события `auth`, `auth_ok`, `open_dm`, `create_group`, `get_history`, `history`, `send_message`, `receive_message`, `conversation_upsert`, `typing`, `call_invite`, `call_accept`, `call_reject`, `call_end`, `webrtc_signal`, `call_log` и HTTP `/api/register`, `/api/login`, `/api/upload`.

Для использования исходного сервера из запроса:

1. Замените server.js вашим файлом.
2. Добавьте `app.use(express.static(path.join(__dirname, 'public')))` **до** обработчика `app.get('/')`, либо поменяйте его путь на `public/index.html` и подключите статику.
3. Установите `cors` и `livekit-server-sdk` дополнительно. В вашем package.json имя зависимости должно быть `"socket.io"`, без Markdown-ссылки.
4. При необходимости добавьте `/api/rtc-config` для выдачи ICE-конфигурации. Без него клиент использует STUN по умолчанию.

Интерфейс не реализует ботов, секретные чаты, администрирование каналов и другие расширенные события исходного сервера. Сообщения в комплектном сервере не имеют сквозного шифрования.

## Файлы и ограничения

- `public/index.html` — разметка
- `public/style.css` — адаптивные стили
- `public/app.js` — клиент и WebRTC
- `server.js` — учебный сервер
- `data.json`, `uploads/` — локальные данные (создаются при использовании)
- `.env.example` — настройки порта и TURN

Прототип не предназначен для открытого production-развёртывания без доработок: нужны БД, контроль доступа к файлам, лимиты запросов, истечение и отзыв сессий, модерация, мониторинг, резервные копии. В текущем сервере вложения доступны по непредсказуемой ссылке, сессии не истекают автоматически. Не используйте реальные личные данные. Иконка прочтения в интерфейсе декоративная, не является подтверждением прочтения.

Демо-аватары загружаются с pravatar.cc, шрифт — Google Fonts; без сети используется системный шрифт. SVG-пейзаж и демонстрационный PDF включены локально.

Проверки: `node smoke.cjs` (после `npx playwright install --with-deps chromium`) и `node api-test.cjs` при работающем сервере. API-тест создаёт тестовые аккаунты.
